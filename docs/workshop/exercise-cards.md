# Exercise Cards

Estas tarjetas contienen **necesidades**, no soluciones. El primer paso siempre es explorar
ambigüedades antes de especificar o implementar.

## A · Harden Client Registration

> Necesitamos mejorar el alta de clientes para evitar clientes duplicados y datos inválidos.

Objetivo pedagógico: Intent -> Clarification -> Spec -> Design -> Tasks -> switch -> Apply.

---

## B · Improve Client Search

> Los usuarios necesitan poder buscar clientes utilizando varios criterios al mismo tiempo.

Objetivo pedagógico: descubrir que el comportamiento actual prioriza un único filtro y
hacer explícita la semántica deseada de combinación.

---

## C · Harden Client Update

> Las reglas de calidad que acordemos para el alta también deben aplicarse cuando se
> modifica un cliente.

Objetivo pedagógico: razonar sobre reglas compartidas y sobre unicidad al actualizar el
mismo registro frente a otros clientes.

---

## D · Add Client Status · reservado para Parte 2

> Necesitamos poder desactivar clientes sin eliminarlos.

Objetivo pedagógico: delta specs, impacto sobre comportamiento existente, review,
evidence, verify y archive.
